# P1 — Content schema and seed data: phase report

Date: 27 Oct 2026. Status: **done locally; CI to be confirmed on the next push** (no commits or pushes are made by Claude Code, per CLAUDE.md rule 10).

## What was built

| Area | Result |
|---|---|
| Source schema (`wb-content/src/source/`) | Serde types for all 13 kinds: country, platform (component-based), system (composite), sensor, weapon, ew_suite, countermeasure, datalink, loadout, base, inventory, doctrine, realism. Field names carry units, and `deny_unknown_fields` is set everywhere, so a wrong suffix (`max_range_kms`) is an error. Doc comments become schema descriptions. |
| Loader (`load.rs`) | Reads `content/**/*.yaml` in sorted order from a virtual file list (`load_files`; WASM-ready for the admin) or a folder (`load_dir`). Checks `kind` against the folder and enforces a global, unique, kebab-case `id`. Resolves `extends` (same kind, cycle detection): the child's own top-level keys replace the parent's, then `overrides` (`a.b[0].c` paths, which must already exist) are applied. Typed reads go through `serde_path_to_error`, so serde errors carry field paths. |
| Validation (`validate.rs`) | Collects **all** errors as `file: path: message`, sorted. See the list after this table. |
| Compiler (`compile.rs`, `compiled.rs`) | SI conversion through `wb_core::units`: km, nm, ft→m; kt, km/h→m/s; min, h→s; deg→rad; kg/h, kg/min→kg/s. Strings are interned into one table, and references become typed indices (`PlatformIx`, `WeaponIx`, …) into per-kind lists sorted by id. Compiled field names carry SI suffixes (`max_range_m`, `turnaround_s`). |
| Pack (`pack.rs`) | `build/content.wbpack` = `WBPK` + format u16 + postcard header `{schema_version, content_version, content_hash}` + postcard body. The hash is BLAKE3 of the body. `decode` checks the magic, format, schema version and hash. The pack holds no paths or timestamps. |
| CLI | `wb content check [--dir]` prints every error and exits 1 on any. `wb content build [--dir] [--out]` prints the hash on stdout and the size on stderr. `wb content schema [--out]` writes the JSON Schema. |
| Schema / TS export | `wb content schema` writes `packages/protocol/src/generated/content.schema.json`: one schema per kind with the meta keys merged in and `kind` fixed. ts-rs exports 80 content types, and `packages/protocol/src/index.ts` re-exports the top-level ones. `pnpm gen` runs both. |
| Realism | `content/realism/default.yaml`, typed `Realism` with every field required. It covers every tuning constant named in doc 02 §3–§14 (list below). |
| Seed content | 67 entries for the Baltic test set (table below), each with sources, confidence and listed estimates. |
| Fixtures and tests | `tests/fixtures/good/` holds a minimal valid set with one entry per kind and a custom `extends` entry. `tests/fixtures/bad/` holds 32 invalid fixtures, each with `# file:` and `# expect:` lines. `tests/content.rs` runs on the real `content/`. |
| CI | The rust job adds `content check` and a build-twice comparison of hash and bytes. The wasm job generates the content types and schema. |

Validation checks:
- references, including wrong-kind references
- unit-suffixed numbers finite and ≥ 0
- probabilities in 0..1
- min < max pairs
- fields required by domain (air needs Mach speeds, ceiling and fuel; ships need knots; ground needs road speed)
- durability model matches the domain
- the sensor block matches `sensor_type`
- platform folder matches category
- station/weapon compatibility in loadouts and system magazines:
  - category intersection
  - internal carriage
  - mass per station
  - cells per station, using `rounds_per_cell` for VLS and launchers
- inventory basing ≤ quantity
- provenance: confidence required; sources non-empty unless `custom: true`; URL scheme; access date; every `estimates` path must exist in the entry
- the `default` realism profile is present

## Schema refinements to doc 04 (not divergences; please confirm)

1. **Meta keys on every entry.** `id`, `kind` and `provenance` are required everywhere, including inventories (doc 04 §3.6 has no id) and systems (§3.4 has no provenance). `custom`, `extends` and `overrides` are optional meta keys. A custom entry needs its own provenance block and may have no sources.
2. **Stations** have `kind: internal | external | vls | launcher` and `capacity` (rounds or cells). Weapons have `rounds_per_cell` (default 1) for quad-packed missiles. Paired pylons can be one station with capacity 2.
3. **Station categories are an open vocabulary** (`aam_medium`, `sylver_a50`, `s400_tube`, …), validated by pattern and matched by intersection. The plan said `StationCategory` would be an enum. A string means a new launcher interface needs no code change (rule 3).
4. **Platform `sensors`** accepts a plain id or `{ sensor, height_m }`. The mounting height feeds the horizon (doc 02 §7); the FREMM radar is at 30 m.
5. **`target_class`** is explicit on platforms and optional on weapons (missiles are targets too). It is the key of `pk_base`.
6. **`durability`** is tagged by `model`: aircraft `p_kill_on_hit`, ship or ground `damage_points`.
7. **Inventory `basing`** is a list of `{ platform, base, count }`, so one type can be based at several bases.
8. **Mach stays a dimensionless Mach number** in the pack. Converting it at sea-level sound speed would be wrong at altitude, and wb-core already leaves the speed of sound to the realism model. dB and dBW stay as they are.
9. **Weapon `profile.kind`** (`rocket | air_breathing | glide | ballistic`) selects the doc 02 §10 energy model. Rocket profiles must give `coast_tau_s` and `min_speed_mach`.
10. **`content/manifest.yaml`** carries `content_version` (semver). `SCHEMA_VERSION = 1` lives in code.

I don't think these need an ADR, because they add detail to doc 04 rather than change it. If you'd rather record them, the ADR would be ADR-019 (Proposed), "Content schema details", and doc 04 §3 would get the updated examples.

## Deviations and decisions

- **serde_yaml kept** (your decision at planning). The `deny.toml` reason now says it is a P1 decision; content files are trusted input.
- **New dependencies** (approved with the plan): `postcard` 1.1.3 (no heapless), `schemars` 1.2.3 (feature-gated), `serde_json` 1.0.154, `serde_path_to_error` 0.1.20. ts-rs now uses its default `serde-compat` feature; the P0 outputs are unchanged.
- **ts-rs prints `failed to parse serde attribute: transparent`** when the `ts` feature builds `UnitId` and `ContactId`. It is cosmetic: ts-rs ignores the attribute and the output is identical. It is not a rustc warning, so `-D warnings` is unaffected.
- **Compiled types copy two source types** (`IrSignature`, `Durability`), because postcard cannot read internally tagged enums or skipped fields. The round-trip test caught this.
- **The string table is in first-use order** rather than sorted, as the plan said. It is still deterministic because the compile order is fixed.
- **The `9m96` entry is one round per cell.** Quad-packing in S-400 tubes is not in the sources, so the S-400 magazine is `{48n6dm: 2, 9m96: 2}` per launcher (estimate). `rounds_per_cell > 1` is exercised by the fixtures.
- **`kh-35u` extends `kh-35`** with a real, non-custom entry, to exercise `extends` on seed data.
- **Extra entries beyond the prompt's list:** the Kronos Grand Naval radar (the FREMM needs a radar for G1), the S-400 and Patriot component platforms and missiles, countries, doctrines, bases and one inventory.
- **The negative-value check reports once.** The generic unit check covers it, and `positive()` skips unit-suffixed fields.
- **`build/` is gitignored** (rule 9). The JSON Schema goes in the already ignored `packages/protocol/src/generated/`.
