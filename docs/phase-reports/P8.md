| Area | Result |

| Admin app (`apps/admin`, ADR-010) | Opens the content folder through the File System Access API. ## Decisions and deviations

- **ADR-045 (Proposed)** records that the test bench reads the truth to score runs, lives in `wb_sim::testbench`, and stays out of the game, `wb-ai` and the hosted build. Please confirm, in particular that `wb-wasm` exporting `TestBench` next to the game engine is acceptable, with the separation held by crate boundary and review (P9 must keep `wb-ai` free of it).
- **B3 and B4 were rewritten.** B3 originally expected a lone fighter that beams the fire-control radar to be killed at least half the time; the default threat reaction defeats most shots (the same energy defeat G6 pins down), so B3 now has two cases per battery: an unaware raider is shot down (≥ 0.6) and a beaming one mostly survives (≤ 0.5). B4 had both the AR-11 and the AI-8; it now covers only the AR-11 (Pk 0.3–0.85, filtered to that weapon). The AI-8 is covered by the calibration rule (every weapon reaches its published range) and the content check, not by an engagement. B2's description now states its band (0.8–1.3) instead of "within 20%". Bands are first estimates; these edits are recorded in the scenario files.
- **No browser session for the admin app.** The File System Access picker needs a person to choose the folder, so I did not drive it. Typecheck, lint and build pass; the browse, form, inventory, compare, diff and test-bench views have not been checked by eye this session. The reference screenshots in `docs/ui-reference/` cover the game, not this tool, so there is no look comparison to list.
