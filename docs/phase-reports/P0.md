## Deviations and decisions

- **`Docs/` renamed to `docs/`** (working tree only) so paths match CLAUDE.md and Linux CI.
- **Extra scenario `scenarios/determinism-probe.yaml`** and a `determinism_probe` system in `wb-sim/src/probe.rs`. It is not gameplay: when enabled, it draws RNG values, runs great-circle maths every tick and moves three bare units in `UnitId` order, so the native-vs-WASM check covers libm, the RNG and ordered iteration rather than an empty clock. It is off unless a scenario sets `determinism_probe: true`.
- **`crates/wb-wasm` is a pnpm workspace member** (`@warboard/wb-wasm`, `package.json` beside `Cargo.toml`) so the game and the Node script share one wasm-bindgen output. No new top-level package.
- **Generated code is not committed** (rule 9): `crates/wb-wasm/pkg/` and `packages/protocol/src/generated/` are gitignored. Run `pnpm gen` after cloning and before `pnpm -r typecheck/build`. CI passes them from the `wasm` job to the `web` job as an artifact.
- **Achieved speed is measured in the worker** (Δsim / Δreal over 1 s), not in the main-thread bridge as doc 06 §2 suggests; it reaches the UI in `TickReport`.
- **`bevy_ecs` 0.19.1**, not 0.20.0: the docs lock 0.19.x.
- **TypeScript 6.0.3**, not 7.0: typescript-eslint does not support 7 yet.
- **`serde_yaml` kept** (user decision). The advisory that actually fires is RUSTSEC-2024-0449 (`unsafe-libyaml`, unmaintained), not RUSTSEC-2024-0320; `deny.toml` ignores 0449 with a reason.
- **`RngPurpose` discriminants are part of the save/replay format**: append only. Known-answer vectors are pinned in `wb-core/src/rng.rs`; changing them changes every hash.
- The state hash encoding is versioned (`hash::FORMAT_VERSION = 1`).
